# STEP 2 — Mom Test 역할 분리 시뮬레이션 프롬프트 (UnitConverter_27)

## 1. STEP 2 실행 프롬프트 (전체)

```
UnitConverter_27 STEP 2 - 역할 분리 Mom Test 시뮬레이션
Role 1 — 인터뷰어: Mom Test 규칙 준수, 질문만
Role 2 — 페르소나: "프로그래밍 수업에서 부분 길이 단위 환산과제를 받은 학생"
  (가상이지만 plausible한 과거 사실만)
3턴 진행:
- Turn 1: 인터뷰어 질문 → 페르소나 답
- Turn 2: 추궁 → 답
- Turn 3: 추궁 → 답
마지막: 표면 문제 vs 진짜 문제 (가상 인터뷰임을 명시)
```

---

## 2. 역할 정의

| Role | 역할 | 규칙 |
|------|------|------|
| **Role 1 — 인터뷰어** | Mom Test 인터뷰어 | 질문만. 솔루션 제안·기술 논의 금지 |
| **Role 2 — 페르소나** | SW 공학 2학년, `UnitConverter.py` 과제 수행 학생 | 가상이지만 **과거 사실**만. "있으면 좋겠다" 금지 |

**페르소나 배경 (참고)**

- meter / feet / yard 길이 변환 과제
- 입력: `meter:2.5` 형식
- 음수·잘못된 형식 검증, 변환 정확도 확인 요구
- README 상수: `1 meter = 3.28084 feet`, `1 meter = 1.09361 yard`

---

## 3. Mom Test 인터뷰 질문 (3턴)

### Turn 1 — 행동·시점 확인

```
이번 과제를 하면서, 코드 말고 직접 단위 환산을 확인한 적이 있나요? 언제였나요?
```

**의도:** 과제 맥락에서 **실제로 한 검증 행동**과 **구체적 날짜** 확보

---

### Turn 2 — 불편·비용 추궁

```
그때 직접 확인할 때, 뭐가 제일 번거로웠나요? 구체적으로 한 번만 말해 주세요.
```

**의도:** 솔루션이 아닌 **가장 아팠던 순간 1건** — 시간·혼란·반복

---

### Turn 3 — 판정·재현 추궁

```
그 문제 때문에 시간을 많이 쓴 날, 최종적으로 뭘로 '맞다/틀리다'를 판정했나요?
```

**의도:** **판정 기준**(교재 vs 구글 vs 눈대중)과 **재현 가능성**(TC 없음) 드러내기

---

## 4. 마무리 프롬프트

```
마지막: 표면 문제 vs 진짜 문제 (가상 인터뷰임을 명시)
```

**출력 형식**

1. **표면 문제** — "~~프로그램 만든다", OCP/YAML 등 **솔루션 섞인** 정의
2. **진짜 문제** — 불편·비용·판정·재현 중심, **솔루션 이름 없음** (한 문장)
3. **Mom Test 증거 3줄** — 페르소나 답변에서 인용
4. **가상 인터뷰**임을 명시

## 5. STEP 1 vs STEP 2 프롬프트 차이

| | STEP 1 | STEP 2 |
|--|--------|--------|
| **방식** | 사용자가 질문, AI가 페르소나 답 | AI가 **역할 분리**로 질문+답 3턴 자동 진행 |
| **페르소나** | 해외 쇼핑 비개발자 | **과제 학생** (README와 정합) |
| **턴 수** | 7문항 (자유 인터뷰) | **3턴** (추궁 구조 고정) |
| **증거 성격** | 실제 인터뷰 흐름 시뮬 | **가상** plausible 사실 |
